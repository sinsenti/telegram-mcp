# Domain docs

This repository uses one domain context.

## Read before exploring

- Read the root `GLOSSARY.md` for domain language.
- Read relevant decisions under `docs/adr/` before changing the area they cover.
- If either is absent, proceed. Create them through domain modeling when terms or decisions are resolved.

## Record terms and decisions

- Keep `GLOSSARY.md` limited to domain terms and their definitions.
- Use the glossary's terms when naming concepts in specs, tickets, code, and explanations.
- Record architectural decisions under `docs/adr/NNNN-slug.md` when they capture a meaningful trade-off that is costly to reverse and surprising without context.
- Surface conflicts with an existing decision explicitly before changing it.
